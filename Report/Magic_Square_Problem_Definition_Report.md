## STEP 1 — Observation (관찰)

### 1. 현재 우리가 해결하려는 상황은 무엇인가?

**관찰된 사실:**

- 4×4 격자 위에 **16개의 칸**이 존재하고, 각 칸에는 수가 들어갈 수 있는 **빈 자리**가 있다.
- 사용자(또는 학습자)는 이 격자에 어떤 수를 배치했을 때, 그 배치가 **특정 규칙(행·열·대각선의 합이 모두 같음)** 을 만족하는지 **즉시 알 수 없는** 상태에 놓여 있다.
- 규칙을 만족하는 배치는 **극히 일부**이고, 그렇지 않은 배치는 **압도적으로 많다**. 즉, **유효 상태와 무효 상태 사이의 비대칭**이 관찰된다.
- 사람이 손으로 합을 맞추려 할 때, **행 4개 + 열 4개 + 대각선 2개 = 10개의 합 조건**을 동시에 추적해야 하며, 그 과정에서 **반복적인 검산·수정·되돌리기**가 발생한다.
- 어떤 배치는 다른 배치를 **회전·반사**한 것에 불과하지만, 사람의 눈으로는 그 **동치 관계**가 잘 드러나지 않는다.

**핵심 관찰 한 문장:**

> **"16개의 수와 10개의 동시 제약 사이에서, 어떤 배치가 모든 제약을 동시에 만족하는지 사람이 직관적으로 판별·추적·비교하기 어려운 상태가 지속된다."**

---

### 2. 왜 4×4 마방진 문제를 다루는가?

**관찰된 특성 (행위·목적이 아닌 문제 자체의 성질):**

| 특성 | 관찰 내용 |
|------|----------|
| **크기의 적절성** | 3×3은 해가 1개로 탐구 여지가 적음. 5×5 이상은 해가 수억 단위로 폭발. 4×4는 본질적으로 다른 해 880개 — 손으로는 많고, 컴퓨터로는 충분히 적은 **중간 규모** |
| **제약의 구조성** | 16개 변수 + 10개 합 제약 + AllDifferent — CSP·백트래킹·가지치기의 전형적 구조 |
| **검증 vs 생성 비대칭** | 유효 여부 **확인은 쉽고**, 유효 배치 **생성·열거는 어렵다** |
| **대칭과 동치** | 회전 4 × 반사 2 = 8가지 대칭. 상태 공간 축소·중복 제거 주제와 연결 |
| **결과의 시각성** | 4×4는 한 화면에 모두 보이며, 정오를 눈으로 즉시 확인 가능 |

---

### 3. 이 문제가 등장하는 학습·시스템 설계 맥락

| 맥락 | 등장 방식 |
|------|----------|
| **(a) 알고리즘·자료구조** | 백트래킹, 순열 생성, 가지치기, 불변식 유지 |
| **(b) CSP** | 변수 16, 도메인 {1..16}, 합 제약 + AllDifferent |
| **(c) 이산수학·조합론** | 마법합 \(M_n = n(n^2+1)/2\), 본질적 해 880개, 대칭군 |
| **(d) 소프트웨어 설계** | 검증기·생성기·풀이기 분리, 관심사 분리 |
| **(e) 교육·인지** | 규칙은 단순, 결과 공간은 거대 — 규칙→탐색→일반화 |
| **(f) 검증·테스트 설계** | 단위 테스트, 속성 기반 테스트 연습 대상 |

### STEP 1 산출물 요약

| 관찰 항목 | 내용 |
|----------|------|
| 관찰된 상황 | 16개 자리 + 10개 합 제약이 동시 작용하는 **유효 상태가 희소한 격자 공간** |
| 관찰된 비대칭 | **검증은 쉽고, 생성·열거·풀이는 어렵다** |
| 관찰된 구조 | **순열 제약 + 합 제약 + 대칭군**의 결합 |
| 관찰된 규모 | 본질적 해 880개, 전체 순열 약 \(2.09 \times 10^{13}\) |
| 등장 맥락 | 알고리즘, CSP, 이산수학, 모듈 설계, 교육, 테스트 설계 |

## STEP 2 — Why #1

### Q. 왜 마방진을 "완성"해야 하는가?

### A. (가정된 답)

> **"16개의 수를 임의로 배치하는 것만으로는 거의 항상 마방진이 되지 않기 때문이다. 사용자(또는 시스템)는 '제약을 모두 만족하는 한 점'에 도달해야 의미 있는 결과를 얻는다. 그러나 그 한 점은 거대한 배치 공간 속에서 극히 드물게 존재하므로, '완성'이라는 행위 없이는 이 문제 자체가 시작되지도, 끝나지도 않는다."**

마방진 문제는 **"완성 상태"라는 목표점이 존재해야만 비로소 정의되는 문제**이다.

---

### 이 답에서 드러나는 불편함·구조적 문제

| # | 구조적 문제 | 내용 |
|---|------------|------|
| ① | **유효 상태의 극단적 희소성** | 전체 \(16! \approx 2.09 \times 10^{13}\) 중 마방진(대칭 포함) 7,040개. 비율 약 \(3.4 \times 10^{-10}\). 무작위 시도는 사실상 작동하지 않음 |
| ② | **이진(all-or-nothing) 보상 구조** | 7/8 행·열이 맞아도 마지막 하나가 어긋나면 실패. 부분 진척이 부분 점수를 주지 않음 → 피드백·중간 보상 부재 |
| ③ | **제약의 상호 의존성** | 한 칸 변경이 행·열·대각선에 동시 영향. "두더지 잡기" 현상. 전역 일관성 vs 국소적 작업의 간극 |
| ④ | **종결 조건의 모호한 체감** | "완성된 것 같다"와 "실제 완성" 사이 거리. 10개 합 검사 필요 → 신뢰 가능한 외부 판정자 필요 |
| ⑤ | **공간 탐색의 비가시성** | 진척·남은 후보 수가 눈에 보이지 않음 |
| ⑥ | **의미의 이항성이 만든 설계 부담** | 출력은 1비트(완성 여부), 입력 처리는 비대칭적으로 무거움 → 모듈 분해 필요성 |

**Why #1 핵심 한 줄:**

> **"완성은 드물고, 부분은 보상되지 않으며, 한 칸의 변경은 전역에 영향을 준다."**

## STEP 3 — Why #2

### Q. 왜 단순 계산이 아니라 "프로그램"으로 구현하는가?

### A. (가정된 답)

> **"단순 계산은 '한 번의 정답'은 줄 수 있지만, '반복 가능하고, 신뢰할 수 있고, 일반화된 정답 절차'는 주지 못하기 때문이다. 마방진 문제는 본질적으로 같은 규칙을 수많은 사례에 적용해야 하므로, 절차 자체를 외부화·고정화·자동화하지 않으면, 사람은 매번 같은 실수를 다시 하고, 같은 검산을 다시 해야 한다."**

---

### 네 가지 관점 분석

#### ① 반복 가능성 (Repeatability)

| 단순 계산 | 프로그램 |
|----------|---------|
| 매번 규칙을 사람이 재구성 | 한 번 정의, 무한 호출 |
| 상태가 보존되지 않음 | 같은 절차·같은 결과 보장 |
| 사례 증가 시 피로 가속 누적 | 1회 사고 비용 → N회 결과 |

**구조적 가치:** 사고 비용의 구조적 차이 — "1회의 사고 비용으로 N회의 결과"

---

#### ② 검증 자동화 (Validation Automation)

| 단순 계산 | 프로그램 |
|----------|---------|
| 행·열·대각선·중복 11번 별도 작업 | 동일·완전한 검사 자동 수행 |
| 검산의 검산이 필요 (자기 참조) | 외부 참조 진리(reference truth) |
| 거짓 양성 위험 | 검증·구성의 분리 → 신뢰의 구조 |

**구조적 가치:** "검증"과 "구성"이 분리되면 신뢰 가능한 시스템이 된다.

---

#### ③ 오류 방지 (Error Prevention)

| 단순 계산 | 프로그램 |
|----------|---------|
| 오류 인식 시점이 늦음 (다 푼 뒤) | 불변식 위반 시 즉시 감지 |
| 역추적 어려움 (중간 상태 미기록) | 재현 가능한 실패 |
| 같은 오류 반복 | 입력 단계에서 범위·중복 차단 |

**구조적 가치:** 프로그램은 오류를 숨기지 않고 드러낸다.

---

#### ④ 규칙 기반 사고 훈련 (Rule-based Thinking)

| 단순 계산 | 프로그램 |
|----------|---------|
| 암묵적 규칙 ("당연히 대각선도…") | 명시적 술어(predicate) |
| 말로만 아는 규칙 | 데이터↔규칙↔절차 분리 |
| 변형 시 처음부터 재사고 | 규칙 교체만으로 새 문제 정의 |

**구조적 가치:** 프로그램화는 "문제를 푸는 훈련"이 아니라 **"문제를 정의하는 훈련"**이다.

---

### Why #2 통합 요약

| 관점 | 본질적 차이 |
|------|------------|
| 반복 가능성 | 사고 비용의 구조적 차이 |
| 검증 자동화 | 신뢰의 구조 |
| 오류 방지 | 실패의 가시성 |
| 규칙 기반 사고 | 이해의 깊이 |

**Why #2 핵심 한 줄:**

> **"프로그램은 규칙을 외부화하여 신뢰·반복·일반화를 가능하게 한다."**

**드러난 함의:** 검증·생성·풀이가 **분리 가능한 모듈**임이 보임.

## STEP 4 — Why #3 (핵심 발견)

### Q. 왜 이 문제를 TDD 방식으로 설계하려 하는가?

### A. (가정된 답)

> **"마방진 문제는 '무엇이 옳은가'를 '어떻게 만드는가'보다 먼저, 더 쉽게, 더 정확하게 말할 수 있는 문제이기 때문이다. 즉, 이 문제는 본질적으로 명세(spec)가 구현(impl)보다 가벼운 문제다. 검증은 단순 합·중복 검사로 충분하지만, 생성·풀이는 거대한 탐색을 요구한다. 이 비대칭이 존재하는 곳에서는, '판정 기준을 먼저 박아두고, 그 기준을 통과하도록 점진적으로 구성하는' TDD가 가장 잘 작동한다."**

---

### 1) 무엇이 통제되어야 하는가?

| 통제 대상 | 내용 |
|----------|------|
| **(a) 입력의 형태와 도메인** | 항상 4×4, 유한 정수 도메인, 완전/부분/빈 격자 구분 |
| **(b) 상태의 의미** | 유효+완성 / 유효+미완성 / 무효 — 셋 중 정확히 하나 |
| **(c) 판정의 결정성** | 같은 격자 → 언제 어디서나 같은 결과 (순수 함수) |
| **(d) 변경의 추적 가능성** | 한 칸 변경이 어떤 제약에 영향하는지 추적 가능 |
| **(e) 비결정성의 격리** | 무작위성은 주입 가능한 외부 자원으로 통제 |

---

### 2) 어떤 불변 조건(Invariant)이 존재하는가?

| 불변식 | 내용 |
|--------|------|
| **(i) 도메인** | 모든 값은 정해진 유한 집합 안, 서로 다름 (AllDifferent) |
| **(ii) 합 (마법합 M)** | \(M = n(n^2+1)/2\), n=4일 때 M=34. 모든 행·열·주대각선 합 = M |
| **(iii) 전체합** | \(1+2+\cdots+16 = 136 = 4 \times 34\) — M은 도메인의 산술적 결과 |
| **(iv) 부분 일관성** | 부분 격자에서도 이미 결정된 부분합 제약은 위반 불가 |
| **(v) 대칭 닫힘** | 회전·반사 변환 후에도 마방진 (위수 8) |
| **(vi) 동치** | 같은 orbit → 하나가 마방진이면 다른 하나도. 본질적 해 880개 |

---

### 3) 왜 입력/출력이 명확해야 하는가?

| 이유 | 설명 |
|------|------|
| **(a) 입력이 닫혀 있다** | 격자(또는 부분 격자) — 외부·시간·사용자 변덕에 비의존 |
| **(b) 출력이 이산적** | Boolean, 격자, 격자 집합, 정수 — 유한·열거·비교 가능 |
| **(c) 불변식 검사 가능** | 출력이 격자면 즉시 불변식 검사 가능 |
| **(d) 모듈 분해 가능** | 검증기·풀이기·생성기·열거기 각각 입출력 계약 = 테스트 정의 |
| **(e) 사용자 신뢰** | "무엇을 넣으면 무엇을 받는다" — 블랙박스 방지 |

---

### Why #3 핵심 발견

| 발견 | 내용 |
|------|------|
| 비대칭의 발견 | **검증은 가볍고, 구성은 무겁다** — 명세가 구현보다 작다 |
| 불변식의 발견 | 도메인·합·전체합·부분 일관성·대칭·동치 — **다층 불변식** |
| 계약의 발견 | 입출력이 **이산·닫힘·유한** — 곧바로 테스트화 가능 |

**Why #3 결정적 한 줄:**

> **"이 문제는 '옳음을 먼저 적을 수 있는' 문제이며, 그래서 TDD에 적합하다."**

## STEP 5 — 진짜 문제 정의

### 1. 표면 문제 정의 (잘못된 정의)

> **"4×4 마방진을 만드는 프로그램을 작성한다."**

**결함:**

| # | 결함 | 설명 |
|---|------|------|
| (a) | 목적이 '만드는 행위'에 갇힘 | 검증·생성·풀이·열거·비교 중 "생성"만 문제처럼 보임 |
| (b) | 옳음에 대한 진술 없음 | 행·열·대각선 합, AllDifferent, 도메인 모두 암묵적 |
| (c) | 입출력 형태 없음 | 계약(contract) 부재 → 외부 기준 없음 |
| (d) | 불변식 보이지 않음 | 유지되어야 할 것이 정의에 없음 |
| (e) | 훈련 의도 누락 | 왜 이 문제를 다루는지, 무엇을 배우려 하는지 없음 |

---

### 2. 개선된 문제 정의 (정확한 정의)

> **"유한한 정수 도메인 위에 정의된 4×4 격자에 대해, '마방진(magic square)'이라는 술어(predicate)를 명시적이고 결정적인 규칙으로 외부화하고, 임의의 격자 상태(완성·부분·빈 격자)에 대해 그 술어의 충족 여부와 도달 가능성을 신뢰 가능하게 판단하는 것이 이 문제의 본질이다."**

**포함 요소:**

| 요소 | 내용 |
|------|------|
| **(a) 대상 영역** | 4×4 격자, 유한 정수 도메인(예: 1~16), AllDifferent |
| **(b) 술어** | "마방진" = 합 제약 + 도메인 제약 + AllDifferent의 명시적 결합 |
| **(c) 상태 분류** | 충족(satisfied) / 부분 일관(partially consistent) / 위반(violated) |
| **(d) 활동의 일반화** | 검증·풀이 가능성·생성·열거·분류 — 모두 같은 술어 공유 |
| **(e) 판단의 신뢰성** | 외부·재현 가능·결정적 판정 |
| **(f) 명시적 외부화** | 규칙·도메인·상태·계약이 시스템 표면에 드러남 |

**한 문장 요약:**

> **"마방진 문제는 '격자 위의 술어를 외부화하고, 그 술어를 모든 활동의 공통 기준으로 삼아, 임의의 상태에 대해 신뢰 가능한 판단을 가능하게 만드는 일'이다."**

---

### 3. 이 문제의 핵심 Invariant

| # | 불변식 | 내용 |
|---|--------|------|
| **(I)** | 도메인 | 각 칸은 유한 정수 집합 안, 채워진 값은 서로 다름 |
| **(II)** | 마법합 | \(M = n(n^2+1)/2\), n=4 → M=34. M은 도메인의 산술적 결과 |
| **(III)** | 합 균등 | 모든 행·열·주대각선 합 = M (동시) |
| **(IV)** | 전체합 일관성 | 전체 합 = \(n \times M\) = 136 |
| **(V)** | 부분 일관성 | 부분 격자에서도 결정된 합 제약은 위반 불가 |
| **(VI)** | 대칭 닫힘 | 회전·반사에 대해 마방진 집합이 닫혀 있음 → 본질적 해 880 |
| **(VII)** | 판정 결정성 | "마방진인가?" 답은 시간·환경·실행 횟수에 무관하게 동일 |

**층 구조:** 데이터(I) → 산술(II, IV) → 구조적 제약(III, V) → 대칭(VI) → 판정 성질(VII)

---

### 4. 우리가 실제로 훈련하려는 사고 능력

| # | 능력 | 설명 |
|---|------|------|
| **1** | **규칙의 외부화** | 암묵적 규칙을 언어·기호·계약으로 끌어내기 |
| **2** | **불변식 중심 사고** | 변화보다 "변하지 않아야 할 것"을 먼저 진술 |
| **3** | **계약 기반 사고** | "이 입력 → 이 출력" 명시적 약속을 먼저 적기 |
| **4** | **상태 분류 사고** | 충족/부분 일관/위반 — 모호함 없는 분류 |
| **5** | **검증과 구성의 분리** | "무엇이 옳은가"를 먼저, "어떻게 만드는가"는 뒤로 |
| **6** | **대칭과 동치 사고** | 표면적 차이 vs 본질적 동일, "세는 단위" 정의 |
| **7** | **모듈 분해 사고** | 검증·생성·풀이·열거의 관심사 분리 |
| **8** | **Spec-First 사고** | 결과를 먼저 진술, 길은 뒤에서 채움 |

**훈련의 본질:**

> 마방진을 다룰 줄 아는 사람이 아니라, **'규칙을 외부화하고, 불변식을 진술하고, 계약을 정의하고, 상태를 분류하고, 검증을 구성보다 먼저 두는' 사고 습관**을 가진 사람. 마방진은 그 습관이 가장 또렷하게 드러나는 **연습용 무대**이다.

## 종합 요약

### 단계별 흐름

```
STEP 1 (관찰)
  → 무엇이 보이는가: 희소한 유효 상태, 검증/구성 비대칭, 대칭 구조

STEP 2 (Why #1)
  → 왜 "완성"이 필요한가: all-or-nothing, 전역 제약, 종결 판정 필요

STEP 3 (Why #2)
  → 왜 "프로그램"인가: 규칙 외부화 = 신뢰·반복·일반화

STEP 4 (Why #3)
  → 왜 "TDD"인가: 명세 < 구현, 불변식 풍부, 입출력 = 테스트

STEP 5 (정의)
  → 진짜 문제: 술어 외부화 + 공통 기준 + 신뢰 가능한 판단
```

### 핵심 결론 3줄

1. **진짜 문제**는 "마방진을 만드는 것"이 아니라, **"마방진이라는 술어를 외부화하고 모든 활동의 공통 기준으로 삼는 것"**이다.
2. **핵심 불변식**은 도메인 → 마법합 → 합 균등 → 전체합 → 부분 일관 → 대칭 → 판정 결정성의 7층 구조이다.
3. **훈련 목표**는 마방진 풀이 능력이 아니라, **규칙 외부화·불변식·계약·상태 분류·검증/구성 분리·Spec-First** 사고 습관이다.

## 부록: 용어 정리

| 용어 | 정의 |
|------|------|
| **마방진 (Magic Square)** | n×n 격자에 1~n²를 한 번씩 배치하여 모든 행·열·주대각선 합이 같은 배치 |
| **마법합 (Magic Constant)** | \(M = n(n^2+1)/2\). n=4일 때 M=34 |
| **술어 (Predicate)** | 격자가 마방진인지 참/거짓으로 판정하는 명시적 규칙 |
| **불변식 (Invariant)** | 모든 유효 상태에서 항상 참인 명제 |
| **본질적으로 다른 해** | 회전·반사로 변환할 수 없는 서로 다른 마방진. 4×4에서 880개 |
| **TDD** | Test-Driven Development. 판정 기준(테스트)을 먼저 작성하고 구현을 뒤따르게 하는 방식 |
| **Spec-First** | 명세(규칙·계약·불변식)를 구현보다 먼저 진술하는 사고 방식 |
